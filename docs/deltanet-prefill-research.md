### 1. Exact gated delta recurrence in YOUR layout (S is K x V, thread j owns column S[:,j]) and its closed-form unrolling over a chunk — this is the identity everything else follows from.

Per value head, tokens r=1..C in the chunk, S_0 = state after the previous token. Inputs: q_r,k_r in R^128 (L2-normalised, q additionally scaled by 128^-0.5), v_r in R^128, beta_r=sigmoid(b_r) in (0,1), g_r = -exp(A_log)*softplus(a_r+dt_bias) <= 0, alpha_r = exp(g_r).
Sequential (what dn_delta_mc does): S_r = alpha_r*S_{r-1} + k_r d_r^T,  d_r = beta_r*(v_r - alpha_r*S_{r-1}^T k_r),  o_r = S_r^T q_r.
Define G_r = sum_{m<=r} g_m, gamma_r = exp(G_r) (gamma_0=1), and the pairwise decay Lambda[r,i] = gamma_r/gamma_i = prod_{m=i+1..r} alpha_m for i<=r (Lambda[r,r]=1), 0 for i>r.
Unrolled: S_r = gamma_r*S_0 + sum_{i<=r} Lambda[r,i] k_i d_i^T.
Substituting into d_r gives a unit-lower-triangular linear system for the C pseudo-values d_r (rows of D, C x 128):
  d_r = beta_r v_r - beta_r gamma_r S_0^T k_r - sum_{i<r} beta_r Lambda[r,i] (k_r . k_i) d_i.
This is the WY/UT-transform: the C Householder-like factors prod alpha_i(I - beta_i k_i k_i^T) collapse into I - sum w_i k_i^T with pseudo-values solved by one small triangular solve (DeltaNet paper Sec. 3, Eq. 6; Gated DeltaNet Sec. 3.3: u~_r = beta_r(v_r - sum_{i<r} u~_i (gamma_r/gamma_i) k_i^T k_r)).

_Source:_ arXiv 2406.06484 Sec 3 Eq.(6)-(10); arXiv 2412.06464 Sec 3.3; verified against fla/ops/gated_delta_rule/naive.py naive_recurrent_gated_delta_rule (h = h*exp(g); v -= h^T k; v *= beta; h += k v^T; o = q^T h) which is exactly your kernel.

_Actionable:_ Keep your S layout (K x V, column-per-thread); the chunk form below is written directly in that layout so no transposes are needed. Everything in the chunk is separable per V-column j, so the column-per-thread mapping survives.


### 2. Chunkwise algorithm, exact matrix form (C tokens, K=V=128), in your layout. Four equations; only three of them touch S.

Let Q,K,V in R^{C x 128} (rows = tokens), beta, gamma in R^C, K_beta = diag(beta) K, V_beta = diag(beta) V.
(1) Lambda (C x C): Lambda[r,i] = exp(G_r - G_i) for i<=r else 0. Lambda_strict = same with the diagonal zeroed.
(2) A = (K_beta K^T) ⊙ Lambda_strict   (C x C, strictly lower; A[r,i] = beta_r * Lambda[r,i] * (k_r . k_i), i<r).
    T = (I + A)^{-1}   (unit lower triangular; paper Eq.10 is T = (I + tril(diag(beta) K K^T, -1))^{-1} diag(beta) — the diag(beta) is folded into K_beta/V_beta in code). NOTE the sign: it is I PLUS the strictly-lower part of diag(beta)KK^T ⊙ Lambda; the '(I - tril(...))^{-1}' in your prompt is a sign slip (FLA writes attn = -(k_beta@k^T)⊙L then substitutes, which is the same thing).
(3) Pseudo-values / delta targets:  D = T * (V_beta - diag(gamma) K_beta S_0)          (C x 128)
    Equivalently the FLA/HF factored form: U = T V_beta ('new_values'), W = T diag(gamma) K_beta ('k_cumdecay'), D = U - W S_0. NB: decay is applied to K_beta BEFORE T (T diag(gamma) K_beta), not after — this follows from the derivation and matches the code.
(4) Output:  O = diag(gamma) Q S_0 + ((Q K^T) ⊙ Lambda) D           (C x 128; the mask INCLUDES the diagonal because o_r reads S_r after its own update).
(5) New state:  S_C = gamma_C S_0 + (diag(gamma_C/gamma) K)^T D  = gamma_C S_0 + sum_r Lambda[C,r] k_r d_r^T   (128 x 128).
Ungated special case (gamma=1) is exactly the DeltaNet paper's Eq.(8)-(9): S_[t+1] = S_[t] + (U - W S_[t]^T)^T K, O = Q S_[t]^T + (Q K^T ⊙ M)(U - W S_[t]^T) (paper's S is V x K; yours is the transpose, hence W S_0 instead of W S^T).
The state S_C produced by (5) is algebraically identical to running the sequential recurrence over the C tokens, so decode continues from it unchanged.

_Source:_ fla/ops/gated_delta_rule/naive.py naive_chunk_gated_delta_rule (verbatim: L_mask=((decay_i - decay_j).tril().exp()).tril(); attn=-((k_beta@k^T)*L_mask) with diagonal masked; forward-substitution loop; k_cumsum=attn@v; k_cumdecay=attn@(k_beta*decay_exp); v_new=v_i - k_cumdecay@S; o = (q_i*exp(decay))@S + attn_qk@v_new; S = S*exp(decay_last) + (k_i*exp(decay_last-decay))^T @ v_new). Same in transformers qwen3_next torch_chunk_gated_delta_rule (pairwise_decay masked to -inf then exp; solve_triangular(unitriangular=True); key *= exp(cum_decay[-1]-cum_decay); chunk_decay=exp(cum_decay[-1])).

_Actionable:_ Implement form (3) (fold S_0 into the RHS and do ONE triangular solve) when a pass = one chunk: it needs one read of S (for both diag(gamma)K_beta S_0 and diag(gamma)Q S_0, fused), one C-step forward substitution per column, one C x C by C x 128 product, one rank-C update + write of S. Use the factored U/W form only if you want to precompute the S-independent part for many chunks in one high-occupancy dispatch (that is what FLA does with chunk_size 64).


### 3. The triangular solve is trivial at C<=16: forward substitution row by row, no pivoting, always well-defined (unit diagonal).

Row-recursive form used by both FLA naive code and the HF export path (verbatim: attn = -A; for i in 1..C-1: attn[i,:i] += sum_j attn[i,j]*attn[j,:i]; attn += I). That computes X = T - I via x_r = -a_r - sum_{i<r} a_{r,i} x_i. You do not even need T: solve (I+A) D = R directly per column j: for r=0..C-1: D[r,j] = R[r,j] - sum_{i<r} A[r,i]*D[i,j]. Cost per column: C(C-1)/2 FMAs (120 at C=16, 28 at C=8), serial in r but each step is a length-<=15 dot, versus the sequential kernel's 128-length dependent reductions per token. FLA's production kernel (solve_tril.py) inverts (I+A) in fp32 ('IEEE' dot precision) via 16x16 forward substitution plus block-Schur merges for 32/64 — that machinery only matters for C>=32. Stability: with ||k||_2 = 1 and beta in (0,1), the eigenvalues of I - beta k k^T are 1 (mult. 127) and 1-beta (DeltaNet paper Sec 3.1), the product is a contraction, and entries of A satisfy |A[r,i]| <= beta_r*Lambda[r,i] < 1; the solve is benign in f32 for C<=16.

_Source:_ fla/ops/delta_rule/naive.py delta_rule_chunkwise; fla/ops/utils/solve_tril.py (solve_tril_16x16_kernel, merge_16x16_to_32x32/64x64, output fp32); arXiv 2406.06484 Sec 3.1 eigenvalue remark, 'inverse of lower triangular matrices could be solved efficiently using forward substitution'.

_Actionable:_ Do the solve in f32 in-thread (no barriers needed once A is in workgroup memory). Never compute T explicitly for C<=16; substitute directly against the RHS columns.


### 4. Shape / work map for dState=128, chunk C in {4,8,16}, per value head h, per pass — and a concrete WGSL workgroup plan that keeps your column-per-thread mapping.

Shared (workgroup) memory: Ks[C][128] f32 (K rows) = 2/4/8 KB for C=4/8/16; Qs[C][128] same (or read Q rows straight from the storage buffer: uniform address across threads = broadcast, cached); A[C][C], P[C][C], Lambda[C][C], beta[C], gamma[C], lamC[C] (= Lambda[C-1][r]) — <=2 KB. Total 6/10/18 KB (C=4/8/16 with Q in shared) — fits 32 KB; at 16 KB budget keep Q in storage or use C<=8.
Registers per thread (thread j = V column): s[128] (its S column), R[C], D[C], Oi[C].
Steps (per pass, one workgroup of 128 threads per head; barriers marked):
 S0. Load K,Q rows into shared (thread j loads element j of every row: coalesced). Compute G_r, gamma_r, Lambda (thread 0 or every thread redundantly, C^2 exps). BARRIER.
 S1. Pairwise dots: assign pairs to threads. A[r][i] = beta_r*Lambda[r][i]*dot(Ks[r],Ks[i]) for i<r: C(C-1)/2 dots (6/28/120) of length 128; P[r][i] = Lambda[r][i]*dot(Qs[r],Ks[i]) for i<=r: C(C+1)/2 (10/36/136). At C=16 that is 256 dot products -> exactly 2 per thread. BARRIER.
 S2. s[i] = S[h][i][j], i=0..127 (row-major S -> coalesced across j). 1 read of the 64 KB state per head per pass.
 S3. For r in 0..C-1: ak = sum_i Ks[r][i]*s[i]; aq = sum_i Qs[r][i]*s[i]; R[r] = beta_r*V[r][j] - beta_r*gamma_r*ak; Oi[r] = gamma_r*aq.  2*C*128 FMAs with 2C independent accumulators (the sequential kernel has a 128-long dependent chain per token instead). Shared reads are broadcast (all threads read the same address) -> no bank conflicts.
 S4. Forward substitution: D[r] = R[r] - sum_{i<r} A[r][i]*D[i].  C(C-1)/2 FMAs, no barrier.
 S5. o[r][j] = Oi[r] + sum_{i<=r} P[r][i]*D[i]; write out (feeds the gated RMSNorm unchanged). C(C+1)/2 FMAs.
 S6. s[i] = gamma_{C-1}*s[i] + sum_r lamC[r]*Ks[r][i]*D[r]  (precompute e[r] = lamC[r]*D[r] once); write S[h][i][j].  C*128 FMAs; 1 write of S.
Totals per thread per pass: ~3*C*128 + C^2 FMAs — the SAME FMA count as the sequential kernel (vhat, update, o = 3*128 per token); the gain is (a) all 128-length loops become C-way independent (ILP instead of C*3 dependent 128-chains), (b) S read/written once per pass instead of touched per token, (c) the only serial part is the C-step substitution over C-length rows.
Matrix-op view (per head): [2C x 128]·[128 x 128] (S3), C x C unit-lower solve on a C x 128 RHS (S4), [C x C]·[C x 128] (S5), rank-C update of 128 x 128 (S6); plus S-independent [C x 128]·[128 x C] twice (S1).
Occupancy option: split the 128 K-rows across P threads per column (256 or 512 threads per head, 64 or 32 s-registers each). S3 then needs a shared partial-sum buffer [P][2C][128] f32 (P=2,C=16: 32 KB; P=2,C=8: 16 KB; P=4,C=8: 32 KB) and one barrier; S4/S5 are done redundantly by the P threads of a column (they all read the reduced R), S6 each thread updates its own 128/P slice. This also fixes the 128-f32 private array problem: WGSL var<private> arrays with dynamic indexing spill to scratch on Tint/Metal — fully unroll with constant indices, and prefer 32-64 elements per thread.
GQA note: q,k are per key-head but beta and g are per value-head, so A and P (the Lambda and beta scaling) are per value head; only the raw dot products k_r.k_i and q_r.k_i are shareable across the nVH/nKH heads of a group.

_Source:_ Derived from equations above; FLA chunk kernels use the same decomposition (recompute_w_u = T applied to k*beta*exp2(g) and v*beta; chunk_delta_h state update; chunk_fwd_o).

_Actionable:_ Replace the token loop in dn_delta_mc with S0-S6 for C = tokens-per-pass (4/8, or 16 if you widen the GEMV batch). If a pass ever carries more tokens than C, loop S0-S6 over sub-chunks inside the same dispatch with s[] staying in registers. dn_conv_mc (3-tap causal conv with carried state), the L2 norms, beta/g computation and the gated RMSNorm are per-token and unchanged.


### 5. Numerical caveat 1 (most important for your relDiff~1e-7 validation): compute the pairwise decays as products of per-token alpha, not as exp of differences of a cumulative log-sum.

FLA/HF compute cum_decay = cumsum(g) in f32 (FLA additionally scales by 1/ln2 and uses exp2) and then exp(cum_i - cum_j). For Qwen3-Next g = -exp(A_log)*softplus(a+dt_bias) with A_log initialised log U(0.01,16), so |g_t| can be O(1-100) and G_r over 16 tokens can reach hundreds; f32 absolute error of G is ~|G|*6e-8, which becomes a ~1e-6..1e-5 RELATIVE error in exp(G_r - G_i) — larger than the rounding of everything else. Your sequential kernel multiplies S by alpha_t = exp(g_t) each token, so the bit-closest chunk implementation forms Lambda[r,i] = alpha_{i+1}*...*alpha_r as a running product (C(C-1)/2 multiplies, negligible) and gamma_r = Lambda[r,0]. Also: only exponents <= 0 are ever needed (i<=r); never evaluate exp for i>r — the HF code masks those to -inf before exp precisely because exp of a positive difference can overflow. Underflow: gamma_r can hit f32 denormal/zero for G < -87/-103; the sequential kernel has the identical behaviour (S*alpha repeatedly), and WGSL backends may flush denormals — same on both paths, so no divergence beyond what you already accept.

_Source:_ transformers qwen3_next torch_chunk_gated_delta_rule ('Positive values are masked to -inf before exp to avoid overflow'; cum_decay = decay.cumsum); fla chunk.py chunk_local_cumsum(..., scale=RCP_LN2) with exp2 in wy_fast.py; Qwen3NextGatedDeltaNet: beta = b.sigmoid(); g = -A_log.float().exp() * softplus(a.float() + dt_bias).

_Actionable:_ In S0 compute alpha_r = exp(g_r) once, then Lambda by running products; use Lambda[C-1][r] for the K decay in S6 and Lambda[C-1][0] for gamma_C. Compute beta, g, alpha in f32 exactly as the sequential kernel does (same expression, same order) so the per-token scalars are bit-identical between paths.


### 6. Numerical caveat 2: expected deviation vs the sequential recurrence and how to validate it.

The chunk form reorders sums: o_r accumulates sum_{i<=r} Lambda (k_i.q_r) d_i at once instead of progressively through S, and S_C accumulates rank-C at once. In f32 with L2-normalised q/k (|k_r.k_i|<=1, |beta|<1) expect max relDiff ~1e-6 on outputs and on the final state (vs ~1e-7 you see for your batched-vs-sequential today), i.e. ~10x looser but still ~1000x below the bf16/int quantisation noise of the weights. Cancellation in d_r = beta(v - predicted) is identical in both forms. FLA keeps A, the solve, the pseudo-values and the state in f32 even when q/k/v are bf16 — do not drop any intermediate (A, P, D, s[]) to f16. Padding is exact: a padded token with q=k=v=0, beta=0, g=0 gives d=0, alpha=1 -> S unchanged, o=0, so zero-pad short passes to C and discard pad outputs (this is what FLA/HF do).

_Source:_ fla naive_chunk_gated_delta_rule (all inputs cast to float32, F.pad with zeros); HF torch_chunk_gated_delta_rule (fp32 throughout, pad_size zero padding); fla solve_tril output_dtype=torch.float.

_Actionable:_ Validate per layer: max relDiff of o and of S_C after a C-token pass vs running dn_delta_mc token by token from the same S_0; then greedy-token agreement over a few hundred tokens of a real prompt. Expect 1e-6-ish; anything >1e-4 means the decay ratio or the diagonal-mask convention (strict for A, inclusive for P) is wrong.


### 7. Exact surrounding definitions you must match (Qwen3-Next reference), since q/k normalisation and beta/g feed both paths.

l2norm(x) = x * rsqrt(sum(x^2) + 1e-6) (eps INSIDE the rsqrt on the sum of squares, not on the norm), applied to q and k in f32 (use_qk_l2norm_in_kernel=True); then q *= k_head_dim^-0.5 (=128^-0.5) — linear in q, so it can be applied anywhere. beta = sigmoid(b), g = -exp(A_log)*softplus(a + dt_bias) per value head, f32. Gated RMSNorm: y = (x * rsqrt(mean(x^2)+eps)) * weight * silu(z) — gate multiplied AFTER the weight, in f32. Reference chunk_size: HF default 64; FLA kernel asserts chunk_size in {16,32,64}; DeltaNet paper 'C is usually 64 or 128'. Nothing in the algorithm requires C to be a power of two or >=16 — the papers' choices are tensor-core tile sizes; for you C should equal tokens-per-pass.

_Source:_ transformers/models/qwen3_next/modeling_qwen3_next.py (l2norm, Qwen3NextRMSNormGated, Qwen3NextGatedDeltaNet.forward, chunk_size=64); fla chunk.py ('chunk_size must be 16, 32, or 64 for Gated Delta Rule'); arXiv 2406.06484 Sec 3.

### 8. Caution: the chunk form does not reduce FMAs, so confirm dn_delta_mc really is the 37 ms/token before rewriting.

Your numbers: 4-col pass ~148 ms, 8-col ~296 ms -> ~37 ms marginal per prompt token, vs 111 ms per decode token. A column-per-thread sequential kernel doing 3*128 FMAs per token per thread across 48 layers x nVH heads should cost on the order of a few ms per token even when latency-bound, unless (a) s[] lives in global/scratch memory and each token performs a dependent chain of 128 global loads, or (b) something else (conv, norms, attention layers, per-token dispatches) scales linearly with tokens. The chunk kernel removes the dependent 128-chains (ILP over C accumulators) and touches S once per pass, which is exactly the fix for (a); it does nothing for (b).

_Source:_ Analysis of the numbers in the task context; FMA counts from the shape map above.

_Actionable:_ Use WebGPU timestamp queries (or run the pass with dn_delta_mc stubbed to a no-op) to attribute the 37 ms/token. If dn_delta_mc dominates, the chunk kernel should bring the pass close to the decode cost (weight-stream bound), i.e. prefill approaching C x decode throughput; if it does not dominate, look at per-token dispatch counts and the conv/norm kernels first.

### 12. Option (b) 'all heads x tiles as more workgroups' cannot add parallelism without a cross-workgroup reduction, which forces 2 dispatches per token with S in global memory; not recommended.

Splitting a head across workgroups by COLUMNS needs no reduction but does not increase total threads (still 6144 column-owners), only changes the WG shape - no gain. Splitting by ROWS does add threads but vhat_j = sum_i S[i,j]k_i needs all rows, so each token needs a global barrier: stage A (per row-tile partial vhat/sq -> global partials) + stage B (reduce, d, S tile update, o) = 2 dispatches x nCols tokens x 48 layers = 384-1536 extra dispatches per pass, with S re-read/written from L2 per token (3 x 64 KB/head-token, decay folded into stage B).
