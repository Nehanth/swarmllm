## 2. Routing math (reference implementations)

### transformers `modeling_qwen3_5_moe.py` (main)

```python
class Qwen3_5MoeTopKRouter(nn.Module):
    def __init__(self, config):
        self.top_k = config.num_experts_per_tok
        self.num_experts = config.num_experts
        self.hidden_dim = config.hidden_size
        self.weight = nn.Parameter(torch.zeros(self.num_experts, self.hidden_dim))

    def forward(self, hidden_states):
        hidden_states = hidden_states.reshape(-1, self.hidden_dim)
        router_logits = F.linear(hidden_states, self.weight)  # (seq_len, num_experts)
        router_probs = torch.nn.functional.softmax(router_logits, dtype=torch.float, dim=-1)
        router_top_value, router_indices = torch.topk(router_probs, self.top_k, dim=-1)  # (seq_len, top_k)
        router_top_value /= router_top_value.sum(dim=-1, keepdim=True)
        router_top_value = router_top_value.to(router_logits.dtype)
        router_scores = router_top_value
        return router_logits, router_scores, router_indices

class Qwen3_5MoeSparseMoeBlock(nn.Module):
    def __init__(self, config):
        self.gate = Qwen3_5MoeTopKRouter(config)
        self.experts = Qwen3_5MoeExperts(config)
        self.shared_expert = Qwen3_5MoeMLP(config, intermediate_size=config.shared_expert_intermediate_size)
        self.shared_expert_gate = torch.nn.Linear(config.hidden_size, 1, bias=False)

    def forward(self, hidden_states):
        ...
        shared_expert_output = self.shared_expert(hidden_states_reshaped)
        _, routing_weights, selected_experts = self.gate(hidden_states_reshaped)
        expert_output = self.experts(hidden_states_reshaped, selected_experts, routing_weights)
        shared_expert_output = F.sigmoid(self.shared_expert_gate(hidden_states_reshaped)) * shared_expert_output
        expert_output = expert_output + shared_expert_output
```
Each expert (the `Qwen3_5MoeExperts` forward):
```python
gate, up = nn.functional.linear(current_state, self.gate_up_proj[expert_idx]).chunk(2, dim=-1)   # gate_up_proj: [E, 2*I, H]
current_hidden_states = self.act_fn(gate) * up                                                   # SiLU(gate) * up
current_hidden_states = nn.functional.linear(current_hidden_states, self.down_proj[expert_idx])  # down_proj: [E, H, I]
current_hidden_states = current_hidden_states * top_k_weights[token_idx, top_k_pos, None]
```
The shared expert is an ordinary SwiGLU MLP: `down(silu(gate(x)) * up(x))`, with intermediate size 512.

**The exact algorithm per token**, where x is the post_attention_layernorm output:
1. `logits = W_router · x`, where W_router is [256, 2048] and there is no bias.
2. `p = softmax(logits)` over **all 256** experts, in fp32.
3. `(w, idx) = topk(p, 8)`.
4. `w = w / sum(w)`, i.e. renormalise over the 8 selected. This is **unconditional** in `Qwen3_5Moe`; the `norm_topk_prob` flag does not exist there. In `Qwen3NextTopKRouter` it is `if self.norm_topk_prob:`, and vLLM uses `renormalize=getattr(config, "norm_topk_prob", True)`. Because Qwen3.5/3.6 configs do not set the flag, every implementation ends up renormalising. Mathematically this equals a softmax over the top-8 logits.
5. `routed = Σ_k w_k · down_e(silu(gate_e(x)) ⊙ up_e(x))`.
6. `shared = sigmoid(w_sg · x) · down_s(silu(gate_s(x)) ⊙ up_s(x))`. w_sg is a single [1, 2048] row, so this is **one scalar gate per token**.
7. `out = routed + shared`, then the residual add. There is no routed scaling factor (llama.cpp's `expert_weights_scale` defaults to 0, meaning it is not applied).

The decoder layer is otherwise the same as dense qwen35: `h = x + attn(input_layernorm(x)); out = h + moe(post_attention_layernorm(h))`. RMSNorm is the "zero-centred" (1+w) form; the llama.cpp converter adds +1 to every `*norm.weight` except `linear_attn.norm.weight`, as it does for dense.

### llama.cpp `src/models/qwen35moe.cpp` `build_layer_ffn` (matches the above)
```cpp
ggml_tensor * moe_out = build_moe_ffn(cur, ffn_gate_inp, ffn_up_exps, ffn_gate_exps, ffn_down_exps, nullptr,
        n_expert, n_expert_used, LLM_FFN_SILU, /*norm_w=*/true, hparams.expert_weights_scale,
        LLAMA_EXPERT_GATING_FUNC_TYPE_SOFTMAX, il, nullptr, ffn_gate_up_exps, ...);
...
ffn_shexp = build_ffn(cur, ffn_up_shexp, ..., ffn_gate_shexp, ..., ffn_down_shexp, ..., LLM_FFN_SILU, LLM_FFN_PAR, il);
ggml_tensor * shared_gate = build_lora_mm(model.layers[il].ffn_gate_inp_shexp, cur);
shared_gate = ggml_sigmoid(ctx0, shared_gate);
ffn_shexp = ggml_mul(ctx0, ffn_shexp, shared_gate);
cur = ggml_add(ctx0, moe_out, ffn_shexp);
```
In `llama-graph.cpp build_moe_ffn`, the path is: `probs = ggml_soft_max(logits)` → `selected = ggml_argsort_top_k(probs, n_expert_used)` → `weights = get_rows(probs, selected)` → with norm_w, `weights /= clamp(sum(weights), 6.103515625e-5, inf)` → expert matmuls via `mul_mat_id` → `silu(gate)*up` → down → multiply by the weight → sum over the 8. The gating function and norm_w are **hard-coded** for this arch, so the GGUF `expert_gating_func` and `expert_weights_norm` keys are not read.

The MTP block (blk.40 in GGUF) is a full-attention block followed by the same MoE FFN (router, 256 experts and shared expert), plus nextn eh_proj/enorm/hnorm/shared_head_norm.

## 3. llama.cpp GGUF format

### Arch name
`LLM_ARCH_QWEN35MOE` maps to **`"qwen35moe"`** (llama-arch.cpp). The converter class `Qwen3_5MoeTextModel` handles HF `Qwen3_5MoeForConditionalGeneration` / `Qwen3_5MoeForCausalLM` and extends `_Qwen35MRopeMixin, _LinearAttentionVReorderBase` → `Qwen3NextModel` → `Qwen2MoeModel`. `qwen3next` is the separate, older Qwen3-Next-80B arch. llama-bench prints these files as `qwen35moe 35B.A3B Q8_0` / `Q4_0`. The rope type is IMROPE (interleaved M-RoPE), the same as dense qwen35.

### Metadata keys (prefix `qwen35moe.`)
The shared ones are already used by dense qwen35: `block_count`, `context_length`, `embedding_length`, `attention.head_count`, `attention.head_count_kv`, `attention.key_length`/`value_length` (256), `attention.layer_norm_rms_epsilon`, `rope.freq_base`, `rope.dimension_count` (64), `rope.dimension_sections` ([11,11,10,0]), `full_attention_interval` (4), optionally `attention.recurrent_layers` (per-layer bool array), `ssm.conv_kernel` (4), `ssm.state_size` (=linear_key_head_dim, 128), `ssm.group_count` (=linear_num_key_heads, 16), `ssm.time_step_rank` (=linear_num_value_heads, 32), `ssm.inner_size` (=v_head_dim*n_v_heads, 4096), and `nextn_predict_layers` (1, or 0 when MTP is stripped).

The keys that are **new for MoE**:
| key | 35B-A3B value | loader |
|---|---|---|
| `qwen35moe.expert_count` | 256 | `LLM_KV_EXPERT_COUNT` (generic loader) |
| `qwen35moe.expert_used_count` | 8 | `LLM_KV_EXPERT_USED_COUNT`, get_key_or_arr, so it can be per-layer |
| `qwen35moe.expert_feed_forward_length` | 512 | `LLM_KV_EXPERT_FEED_FORWARD_LENGTH`, get_key_or_arr, so it can be per-layer |
| `qwen35moe.expert_shared_feed_forward_length` | 512 | `LLM_KV_EXPERT_SHARED_FEED_FORWARD_LENGTH` |
| `qwen35moe.feed_forward_length` | [UNCONFIRMED value; only used as a fallback: `n_ff_exp = n_ff/n_expert_used` if the expert length is missing] | |
| `qwen35moe.expert_weights_scale` | not written; defaults to 0 (so no scaling) | |

(Verified header dump of a 3.6 GGUF: `general.architecture=qwen35moe`, `block_count=41` (40 trunk + 1 MTP), `expert_count=256`, `expert_used_count=8`, `head_count_kv=2`, `context_length=262144`, `nextn_predict_layers=1` (MTP file) or 0.) Qwen3.5 Q8_0 without MTP reports 733 tensors and 40 layers; with MTP it is 753. This is consistent with the per-layer tensor list below: 30*19 + 10*16 + 3 = 733, plus 20 for the MTP block.

### Per-layer tensors (from `llama_model_qwen35moe::load_arch_tensors`). Shapes are in ggml `ne` order (ne[0] = contiguous/innermost = input dim)

For every trunk layer (both linear and full), the dense `ffn_gate/ffn_up/ffn_down` are **replaced** by:

| tensor name | ggml ne (35B-A3B) | stored type in quantized files |
|---|---|---|
| `blk.N.ffn_gate_inp.weight` (router) | `{n_embd, n_expert}` = {2048, 256} | **F32 always**. The converter forces F32 and llama-quantize skips `ffn_gate_inp.weight` |
| `blk.N.ffn_gate_exps.weight` | `{n_embd, n_ff_exp, n_expert}` = {2048, 512, 256} | quantized (Q8_0 / Q4_0 …) |
| `blk.N.ffn_up_exps.weight` | {2048, 512, 256} | quantized |
| `blk.N.ffn_down_exps.weight` | `{n_ff_exp, n_embd, n_expert}` = {512, 2048, 256} | quantized |
| `blk.N.ffn_gate_inp_shexp.weight` (shared-expert gate) | `{n_embd}` = {2048}; in the file it is {2048, 1} | **F32** (converter-forced; `ggml_n_dims`<2, so llama-quantize never quantizes it) |
| `blk.N.ffn_gate_shexp.weight` | `{n_embd, n_ff_shexp}` = {2048, 512} | quantized |
| `blk.N.ffn_up_shexp.weight` | {2048, 512} | quantized |
| `blk.N.ffn_down_shexp.weight` | `{n_ff_shexp, n_embd}` = {512, 2048} | quantized |
| (optional) `blk.N.ffn_gate_up_exps.weight` | `{n_embd, 2*n_ff_exp, n_expert}` = {2048, 1024, 256} | only when converted with `--fuse-gate-up-exps` (off by default); gate rows first, then up (`view` offset 0 = gate, offset n_ff = up) |

**Stacked expert layout.** GGUF reverses PyTorch dims: the PyTorch tensor `[n_expert, n_ff, n_embd]` becomes ggml ne `{n_embd, n_ff, n_expert}`. So in memory each expert is a contiguous 2D matrix; the expert index is the outermost (slowest) dim. Expert e's gate matrix is rows `e*512 … e*512+511` of a `[256*512 rows × 2048 cols]` row-major matrix. It starts at byte offset `e * nb[2]` with `nb[2] = 512 * rowbytes(2048)`. Each row is one output feature, quantized along the 2048-long input dim, exactly like a normal 2D weight. For down_exps, each expert is `[2048 rows × 512 cols]`, quantized along the 512-long dim.
- Q8_0: gate/up expert slice = 512 × (2048/32·34 = 2176 B) = **1,114,112 B**; down expert slice = 2048 × (512/32·34 = 544 B) = **1,114,112 B**. The whole `ffn_gate_exps` tensor is 285,212,672 B (272 MiB).
- Q4_0: gate/up slice = 512 × 1152 B = **589,824 B**; down slice = 2048 × 288 B = 589,824 B. The whole tensor is 150,994,944 B (144 MiB).
- (WebGPU note: a whole stacked Q8_0 tensor, at 272 MiB, exceeds the default `maxStorageBufferBindingSize` of 128 MiB. Either request a higher limit, bind with an offset/size window, or split it.)

The HF→GGUF conversion (`conversion/qwen.py`, `Qwen2MoeModel.modify_tensors`) splits the HF fused `mlp.experts.gate_up_proj` ([E, 2*I, H]) into gate = `[..., :I, :]` and up = `[..., I:, :]`, and writes them as `ffn_gate_exps` / `ffn_up_exps`. `mlp.experts.down_proj` ([E, H, I]) becomes `ffn_down_exps`. Older per-expert checkpoints (`mlp.experts.{i}.{gate,up,down}_proj.weight`) are `torch.stack`ed on dim 0. The `mlp.gate.weight` router becomes `ffn_gate_inp` and `mlp.shared_expert_gate.weight` becomes `ffn_gate_inp_shexp`.

**All other tensors are unchanged from dense qwen35.** Linear layers have `attn_norm`, `attn_post_norm`, `attn_qkv` {2048, 2*16*128+32*128 = 8192}, `attn_gate` {2048, 4096}, `ssm_conv1d` {4, 8192}, `ssm_dt.bias` {32}, `ssm_a` {32}, `ssm_beta` {2048, 32}, `ssm_alpha` {2048, 32}, `ssm_norm` {128} and `ssm_out` {4096, 2048}. Full layers have `attn_q` {2048, 256*16*2 = 8192} (q plus output gate), `attn_k` {2048, 512}, `attn_v` {2048, 512}, `attn_output` {4096, 2048}, `attn_q_norm` {256} and `attn_k_norm` {256}. The V-head reorder (grouped → tiled) for n_k_heads != n_v_heads applies as in dense qwen35.

Top level: `token_embd` {2048, 248320}, `output_norm`, and `output` {2048, 248320} (not tied).

**MTP block `blk.40`** (only when `nextn_predict_layers=1`): the full-attention tensors above, the full MoE FFN set above, plus `blk.40.nextn.eh_proj` {4096, 2048}, `nextn.enorm` {2048}, `nextn.hnorm` {2048}, and `nextn.shared_head_norm` {2048}. `nextn.embed_tokens` and `nextn.shared_head_head` are optional and absent in practice (it shares the trunk embedding and output). ggml-org also ships the MTP block as a separate small GGUF (`mtp-Qwen3.6-35B-A3B-{Q4_0,Q8_0,BF16}.gguf`); llama.cpp supports this "mtp_only" load when `blk.0.attn_norm` is missing.

gguf-py `MODEL_ARCH.QWEN35MOE` tensor list: TOKEN_EMBD, OUTPUT_NORM, OUTPUT, ATTN_NORM, ATTN_Q, ATTN_Q_NORM, ATTN_K, ATTN_K_NORM, ATTN_V, ATTN_OUT, ATTN_POST_NORM, ATTN_GATE, ATTN_QKV, FFN_GATE_INP, FFN_GATE_INP_SHEXP, FFN_UP_SHEXP, FFN_DOWN_SHEXP, FFN_GATE_SHEXP, FFN_DOWN_EXP, FFN_UP_EXP, FFN_GATE_EXP, FFN_GATE_UP_EXP, SSM_A, SSM_CONV1D, SSM_DT, SSM_NORM, SSM_BETA, SSM_ALPHA, SSM_OUT, and NEXTN_* (6).

**Can the engine (Q4_0 / Q8_0 / F32 / F16) load these?** This is a code-level analysis of `llama-quant.cpp` and `conversion/base.py`; I did not dump these specific files.
- **Q8_0 files (ggml-org, unsloth, bartowski)** are the safest bet. With ftype Q8_0, every ≥2D weight becomes Q8_0, including `output.weight`: the Q6_K bump only applies `if new_type != Q8_0`. The router `ffn_gate_inp`, `ffn_gate_inp_shexp`, `ssm_conv1d`, all norms and 1D tensors (`ssm_a`, `ssm_dt.bias`) stay **F32**. So expect only Q8_0 and F32. [UNCONFIRMED by tensor dump: ggml-org's Q8_0 is produced directly by `convert_hf_to_gguf --outtype q8_0`, which applies the same F32 rules. Check with `gguf_dump` for any stray F16/BF16.]
- **bartowski Q4_0 is NOT pure Q4_0.** llama-quantize defaults put `output.weight` in **Q6_K** (`else if (new_type != GGML_TYPE_Q8_0) new_type = GGML_TYPE_Q6_K`). With an imatrix, which bartowski always uses, `ffn_down*` tensors (this includes `ffn_down_exps` and `ffn_down_shexp`) in the first `n_layer/8` layers become **Q4_1** ("Guard against craziness in the first few ffn_down layers ... Q4_0/Q5_0"). The expected types are Q4_0, Q4_1, Q6_K and F32. Supporting it would need Q4_1 and Q6_K kernels, or a local requantize from Q8_0/BF16 with `llama-quantize --pure … Q4_0` (a community "pure-Q4_0" 3.5 file of 20.1 GB exists privately).
