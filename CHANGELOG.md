# Changelog

All notable changes to SwarmLLM. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- **Long context for the 27B** (docs/tabby-kernel.md): f16 KV cache (half the memory) and split-K flash attention (`attn_flash` / `attn_combine`; the query heads sharing a KV head read each row once; fixed-order merge), used by decode, verify and prefill alike so speculative decoding and split rooms stay exact. 27B rooms get 8192 tokens of context (was 2048). Checked against the f32 path by `tests/e2e/flash_synth.mjs`, including past 2048 tokens. `attnFlash: false` for A/B.
- **Tiled prefill attention** (`attn_flash_t2`): batched passes run two columns per workgroup, so each K/V row is read once per pair instead of once per column (at 8K context, a 16-column prefill chunk otherwise reads each attention layer's 32 MB of K/V 16 times). Bit-identical to the one-column kernel (`tests/e2e/fusion_synth.mjs`, with a mutation check); `attnTile: false` for A/B.
- **Session state**: `exportState` / `importState` and GPU slots (`saveSlot` / `loadSlot`) resume a conversation with bit-identical logits; `harness/statecache.js` keeps states on disk (OPFS) keyed by model, layers and tokens; `harness/prefix.js` picks the longest reusable checkpoint (`tests/e2e/state_synth.mjs`).
- **Tool calls** (`harness/tools.js`): both Qwen formats (XML for Qwen 3.5+/3.8, JSON for Qwen3), prompts, results, and a streaming parser that never shows half a tag; `harness/constrain.js` keeps tool and parameter names to the declared ones.
- Prompt-lookup drafts search the whole context (16K tokens, was 4K), and after a lookup run is accepted in full the next one may run to `engine.maxDrafts` = 15 tokens (replay rollback's limit at 16 batch columns; was 7): a file being copied back goes in verifies of 16 tokens (`tests/e2e/drafts_synth.mjs`: 15-token runs, rejections at draft 1 and 9, 4 and 16 columns, all == plain).
- **int8 KV cache** (`kvQ8: true`, room `?kv=q8`): K/V as int8 with one scale per 32 values (~56% of f16's memory; 32K context on the 27B: 1.2 GB instead of 2.1 GB, spread over the devices). Off by default: same greedy tokens as the f32 path in `tests/e2e/flash_synth.mjs --q8`, logit differences ~3e-5 of the range (f16: ~1e-6); `engine_synth.mjs --q8` checks spec == plain and split == solo with it.
- Agent: tool-name constraint applied while sampling (`engineModel({ tools })`, speculative steps included); context budget that cuts the oldest tool outputs first (`Agent({ budget })`).
- **Agent harness core**: `harness/agent.js` (tool loop with approval for edits), `harness/codetools.js` (list / read / search / edit / write), `harness/workspace.js` (a local folder via the File System Access API, or memory), `harness/engine-model.js` (the loop on a Qwen35Engine with prefix reuse between steps).
- **Sessions** (`harness/sessions.js`): several agent conversations on one engine; parked ones wait in GPU slots, the least recently used spill to disk (OPFS); switching back is bit-exact.
- **Room checkpoints** (`?ckpt=N`, default 2): every device saves its state after each answer (keys ride the frames like reset / rollback), so a regenerate or branch resumes from the longest saved answer instead of re-prefilling.
- **Register-resident DeltaNet kernels** (`dn_delta_mc` for batched passes, `dn_delta` for decode): each thread keeps its column of the recurrent state in registers for the whole pass instead of two global read-modify-write sweeps per token (docs/deltanet-prefill-spec.md, RG=1). Bit-identical to the previous kernels at the 27B's shape (`tests/e2e/dn_delta_synth.mjs`: 0 of 786,432 state values differ); the spec's GB10 microbenchmark: 1.24× at 1 column, 2.03× at 16 for the kernel.
- **Attention softmax on a workgroup per head**, bit-identical (max and exponentials in parallel, the same sequential sum from workgroup memory): it used to be one thread per head doing three serial passes over global memory, a cost that grew with the context.
- **Fused attention glue** (`attn_glue`): the q/gate split, both head norms and the partial rope of an attention layer in one dispatch instead of five, on the decode and batched paths; bit-identical (`tests/e2e/fusion_synth.mjs`, also at the 27B's shape). `attnGlue: false` for A/B. Aimed at Metal, where each dispatch costs 32–71 µs; GPU numbers pending.
- **Fused DeltaNet delta rule and gated norm for decode** (`dn_delta_gn`): both already ran one 128-thread workgroup per value head, so the gated norm now follows in the same workgroup and the head's outputs never go through global memory; bit-identical (`tests/e2e/fusion_synth.mjs`). `dnFuse: false` for A/B. With the attention glue, 112 fewer dispatches per 27B token.
- **Batched attention for verify and prefill passes**: scores, softmax and output for every column in one dispatch each (per-column score rows), instead of three dispatches per column run in turn over a shared scratch; bit-identical (`tests/e2e/fusion_synth.mjs`). −144 dispatches per K=3 verify on the 27B. `attnMC: false` for A/B.
- **One-submit draft chain** (opt-in `?draftchain=1`): the K drafts of a speculative step in one command buffer, the next draft's embedding gathered on the GPU from the argmax; identical drafts.
- **Q8_0 prefill GEMM** (`engine/wgsl/gemm.js` `kernel8`): `ffn_down`, `ssm_out` and `attn_output`, which the 27B file keeps in Q8_0 (~40% of a DeltaNet layer's bytes), now go through the row-stationary GEMM in full-width prefill passes instead of the batched GEMV. On a 27B-shaped synthetic model: relative error vs the GEMV 2.7e-7 (prefill tolerance 2e-3). `gemm8: false` / `engine.gemm8 = false` for A/B. GPU numbers pending.
- **Replay-based rollback** for speculative decoding: one pre-verify state plus each column's inputs instead of 7 full state snapshots per DeltaNet layer; a rejection re-runs the same kernel over the accepted columns (bit-identical). Frees ~6/7 of ~1 GB of snapshot memory on a device holding the whole 27B. `replayRollback: false` for the old path.
- **Batched draft-cache fill** in prefill: one batched pass per chunk instead of one submit (and one pass over the draft layer's weights) per prompt token; rows bit-identical to the per-column fill.
- **Wire guard**: every frame is scanned for NaN/Inf and refused beyond f16's range instead of sending Inf; the swarm map shows each boundary's largest activation.
- Research survey of kernel and scheduling techniques ranked against this engine: `docs/research/kernels-2026-09.md`. Synthetic models with the 27B's real shapes (`synth.mjs --shape 27b`) and of the dense Qwen3 family (`synth_dense.mjs`) for SwiftShader runs.
- **Prompt-lookup drafts**: when an answer repeats something already in the conversation, the tokens that followed the same n-gram earlier are verified as drafts (up to 7 at once, free to produce); otherwise the draft head drafts. New `Qwen35Engine.specStepDrafts`. Output unchanged (synthetic room: answers byte-identical to lookup off; 2-device decode 3.9 → 4.7 tok/s on a deliberately repetitive model; real-model numbers pending).
- **Speed-aware layer split**: "for speed" fills the fastest devices first (ms per layer measured on the room's own answers) and leaves out devices that aren't needed; they stay as ask-only guests and free their GPU.
- **Weights from the room**: before dealing, the host collects which byte ranges each device has cached; a device takes missing ranges from another device over WebRTC and only falls back to the model host on failure (a re-deal in the test room: 26 → 1 requests to the model host).
- **Tensor prefetch**: the next 4 tensors of a shard are requested while one loads, hiding the model host's per-request latency (test room with 300 ms time-to-first-byte: online in 40.8 s instead of 65.6 s; phones keep 1).
- **The room survives a host reload**: the host keeps the conversation in localStorage and a reloaded page offers "resume room"; guests keep knocking for a minute; the room deals again and the conversation continues where it was.
- **Question queue** instead of "busy, try again"; **Continue** a capped answer (byte-identical to an uncapped one) and **Regenerate**; answer length setting.
- **Reactions**, "… is typing", **read aloud** (the device's own speech synthesis), and the **swarm card**: a shareable PNG of the room's model, devices and tok/s.
- The prompt's last 1–4 tokens go round the chain as one frame instead of one lap each; f16 unpack through a lookup table (13× faster per frame).
- Harness: `room_synth.mjs` gained `--isolate` (one cache per device), `--netlag`, `--ttfb`, `--max-new`, `--continue`, `--regen`, `--queue`, `--social`, `--split`, `--redeal-after`, `--reload-after`, `--card`, `--screenshot`.
- **Multi-turn chat** (roadmap 13): the room keeps its caches between questions and prefills only what is new, so follow-ups work ("what did I just ask?") and a long conversation stops paying for its history on every turn. The host tracks the exact tokens every device holds (`room/conversation.js`); anything that is not a strict prefix (a new persona, older turns dropped to fit the context) resets and re-prefills, so correctness never depends on guessing. A "new chat" button, a live context meter, and older exchanges are forgotten (and said so) instead of overflowing.
- **Stop** (roadmap 12): Send turns into Stop while an answer streams, on the host and on the asker's screen (Esc works too); decoding ends after the lap in flight and every screen unlocks.
- **Fail fast and re-deal** (roadmap 12): a device leaving mid-answer fails every lap in flight at once (tabs announce `leaving` on `pagehide`, so it takes one lap rather than an ICE timeout), the room goes "degraded", and the host gets a Re-deal button that splits the model over whoever is still there (cached layers reload in seconds; the conversation is kept). The same button brings in devices that joined after the start. Guests whose host left see "room over" with a way to start a new one. A phone whose tab was killed says so when it comes back.
- **Pipelined prefill**: up to 6 prefill rounds in flight round the chain, so round r+1 runs on the host while round r is on a worker. Same frames in the same order on every device, same output.
- **Draft cache filled from the room's prefill** (roadmap 25): the hidden states the chain returns during prefill now feed the host's draft block, so the first speculative steps after a prompt draft from a warm cache instead of a cold one. `?fill=0` turns it off for A/B runs.
- **Join links and QR** (roadmap 14): `swarmllm.ai/r/ABCD` opens the room and joins with no typing; a share sheet with a QR code (a dependency-free encoder in `room/qr.js`, checked against jsQR), copy and Web Share.
- **Model ladder** (roadmap 14): every model with what the room still needs for it ("27B +7.5 GB"); the select follows the largest model the room can run until someone picks one. Only devices with WebGPU count; the others join as ask-only guests instead of 0 GB peers that break the split.
- **Pre-flight** (roadmap 14): the landing page and join screen say whether this browser can hold layers and, if not, the exact remedy (Linux Chrome flag, Firefox, iOS version, insecure page, blocklisted driver). iPads are no longer classified as Macs.
- **Swarm map and per-hop telemetry** (roadmap 25): workers report compute per frame kind; the host splits each lap into GPUs and wire and shows the chain live on every screen, with a pulse per lap, tok/s and draft acceptance.
- **Show drafts**: tint the words the draft head guessed right and the whole swarm confirmed in one lap.
- **Answer styles**: personas (concise, explain-like-I'm-five, pirate, haiku, "the swarm speaks"), sampling presets (creative, focused, exact/greedy) and a thinking mode for Qwen models whose think block folds away. Save the chat as Markdown.
- Protocol version in `hello`; a tab from another deploy is told to reload instead of failing mid-answer (`PROTOCOL` = 3).
- A synthetic Qwen-3.5-architecture model and SwiftShader harnesses (`tests/e2e/synth.mjs`, `engine_synth.mjs`, `room_synth.mjs`) that run the real engine and the real multi-tab room on a machine with no GPU.
- Room topology is linear, not a mesh: every device keeps one link to the host; chain neighbours connect only when the layers are dealt (`ensureLink`). A 64-device room opens 126 links instead of 2,016. Workers draw the device list from the host's roster. `?signal=host:port` points the room at a self-hosted PeerServer.
- Room emulator (`npm run e2e`): `--devices N --phones K`, local PeerServer, 27B from local disk, room-log error capture, fail-fast on load errors. 16 devices on the 27B verified on GB10.
- Hidden-state wire (`room/transport.js`): activations travel on a dedicated data channel as ≤4.6 KB slices, striped over several peer connections (`?wire=stripeN`, default 4; `?wire=off` to disable). On a 100 ms link a token's hidden state now crosses a hop in 51 ms instead of 152, and a depth-5 verify block in 52 ms instead of 355 (docs/bench-log.md, transport section). Bytes only, output unchanged.
- Multi-token-prediction speculative decoding using the model's built-in draft layer; output is bit-identical to plain decoding. Solo host and device chains.
- Adaptive draft depth (3/5/7) chosen by measured tokens per second; 8 batch columns so a depth-5 verify is a single pass.
- Batched prefill: 4 (now up to 8) tokens per GPU pass, 16 tokens per network round.
- Device autotune for the cooperative GEMV shape at load.
- Binary WebRTC frames and f16 wire format for activations (one third of the original bytes per hop).
- Fused gate/up GEMV with in-kernel SiLU; fused DeltaNet gate + L2-norm pre-pass; accumulate-into-residual matvec variants.
- Bench log, kernel-family profiler, GEMM prefill prototype, research plans and four implementation designs under `docs/` and `docs/research/`.
- A roadmap (`roadmap/`) of 27 items, each mirrored by a tracking issue.

### Changed
- Repository restructured for open source: `engine/` split into focused modules behind a compatible `engine.js` barrel (dense, qwen35, wgsl/*, gguf, tokenizer, sampling, quant, autotune, selftest, safetensors); the room page split into `p2p.html` (markup) + `room.js` + `room/*` helpers; tests, benchmarks, goldens and references moved under `tests/` and `benchmarks/`; `BelloEngine` renamed `DenseEngine`.
- Cooperative GEMV kernels (64 threads per row, coalesced loads, shared-memory reduction): 27B decode 3.6 → 9.0 tok/s plain, 16 tok/s with speculation on a GB10.
- f16 block scales end to end; `unpack4x` dequantization with runtime probe.

### Fixed
- **Dense models (Qwen3 0.6B/1.7B/4B) produced gibberish whenever a device's autotune picked 8 rows per workgroup.** The 4-column batched kernels are built with 4 rows per workgroup, but `engine/dense.js` dispatched `dOut / coopRows` workgroups, so at ROWS=8 half of every batched GEMV's output rows were never written (stale but finite, so no NaN check fired). Every prompt prefill on such a device was corrupted; since each device autotunes on its own, a room broke as soon as any device in the chain picked ROWS=8 (solo on such a device broke too for prompts of 5+ tokens). The dispatch now uses the batched kernels' own rows. `tests/e2e/engine_dense_synth.mjs` checks batched vs one-token hiddens for WG {64, 256} x ROWS {4, 8} (all bit-identical now; ROWS=8 differed by up to 7.1 before), and `room_synth_dense.mjs --rows-per-tab 4,8` reproduces the room (different from solo at the first character before, identical after).
- Speculative steps could draft past the answer cap, so a capped answer forced the next question to re-prefill the whole conversation.
- A review of the new room code: a degraded room queued questions forever; the transport's gap timer could skip a frame that was only late and then run it out of order; host-only messages were accepted from any peer; a malformed ask could lock the host busy; layer labels were not escaped; Continue/Regenerate could run during a re-deal.
- **Workers never reset their recurrent state between questions.** Since the module split, `onData` routed every `ai-*` message to `aiOnData`, whose switch had no case for `ai-reset`, `ai-next`, `ai-layers` or `ai-start-req`. In a split room every question after the first ran the workers' DeltaNet layers from the previous conversation's state; pressing start on a device that was not the biggest did nothing; a reloaded device was re-seated without its upstream neighbour learning its new id. Resets now ride on the frames and the routing is fixed.
- **Chains with two or more workers corrupted their state on the first rejected draft.** A worker forwarded verify frames without the `spec` flag, so the next worker never snapshotted its recurrent state and restored a stale snapshot on rollback. The flag now travels with the frame.
- A rollback and a new-conversation reset could be overtaken by the next frame (separate channels, one lost packet); both now ride in the frame header and the transport delivers frames in send order.
- Lap timers were never cleared: a stale 30 s / 90 s timer could delete a newer waiter with the same position key.
- Device names from other peers went into the load card as raw HTML.
- Solo prefill filled the draft cache at position `i + 1` in its single-token tail, which is only right when the prompt starts at position 0.
- Generation no longer runs past the context window (#31): the room stops before the KV cache would overflow and says "stopped: context full", refuses prompts that leave no room for an answer, and the context is 2048 tokens (was 512). Cache size does not change logits (`tests/test_ctx.js`, bit-identical).
- **`f32ToF16` dropped the rounding carry**, silently halving ~0.03% of all values (e.g. -1.9999911 to -1.0): about 1.4 corrupted numbers per 5,120-float activation frame on every hop of a split room, plus occasional halved Q4/Q8 block scales. The carry now propagates into the exponent; all 65,536 representable f16 values round-trip exactly.
- Tall matvec dispatches over 65,535 workgroups (the LM head at 2 rows per workgroup) were silently dropped; all matvecs now dispatch in 2-D.
- Draft depth selection by lap time could lock a Mac-hosted room at maximum depth (1.5 tok/s); replaced by throughput-based selection.
